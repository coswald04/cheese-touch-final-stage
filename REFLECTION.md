# # Reflection

For this assignment, the biggest thing I repeated by hand was the shared page skeleton. Every page needed the same basic structure with mostly the same navigation links and footer text. Even though each page had a different purpose and layout technique, I still had to copy the same site name, navigation, stylesheet links, and footer across multiple files. After doing it a few times, I started to understand why web components or static site generators are useful as if I made a mistake, there was a good chance I had to check all the other html files to see if I made the same mistake. 

The main thing that broke when I moved files was paths for the linking I was doing. Pages inside the `guide/` folder needed paths like `../styles/site.css` and `../images/logo.svg`, while root pages like `index.html`, `about.html`, and `join.html` used `styles/site.css` and `images/logo.svg`. I also had to adjust navigation links depending on where the page lived. For example, linking to the home page from `guide/index.html` was different than linking to it from `about.html`.

The page I struggled with most was `join.html` because it combined two layout demos: the flex-column page layout and the flex-centering card layout. I had trouble figuring out which element should be the flex container and which element should be the centered card. My biggest issue that I delt was CSS nesting and braces, where some rules did not apply because they were accidentally inside another selector which I feel as though is the biggest con of removing the parent in the selector name. 

A tool I would love is something that would generate a personalized skeleton automatically. It would create the repeated header, nav, footer, stylesheet links, and correct relative paths based on the page’s folder location. I would also want it to generate a basic CSS layout skeleton for each page type, so I could focus more on the content and page-specific styling instead of repeating setup code.
